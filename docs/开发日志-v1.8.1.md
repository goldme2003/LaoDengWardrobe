### 32. v1.6.2 修复自动定位从未发起（app.config.ts 缺失定位权限声明）

```ts
permission: {

    desc: '用于自动获取你所在城市的天气与穿搭推荐'
  }
},
requiredPrivateInfos: ['getLocation'],
```

**涉及文件**：`src/app.config.ts`、`package.json`、`package-lock.json`、`src/data/presets.ts`、PRD/日志重命名为 v1.6.2。

### 16. 修复 emptyGuide 需多次调用才返回（硬超时 / 进程终止条件 / 提示词精简）

**修改时间**：2026-11-15 +08:00
**类型**：修复（云函数）

**问题**：空衣橱引导云函数需多次调用才返回结果（遗留问题见条目 13 的 `ret=-3` / 反复调用），排查确认属函数自身超时与终止条件缺陷。

**根因**：
1. `provider/hunyuan.js` 的 `timeout: 25000` 仅为 socket 空闲超时，不约束总耗时；上游持续缓慢回包时函数会拖到平台 60s 上限被强杀（`ret=-3`），首次调用失败、重试才有机会成功。
2. 响应流未监听 `error` / `aborted`：上游中途断连会触发未捕获异常导致进程崩溃，Promise 永不落定。
3. 兜底文案未缓存：模型不可用时每次进入空衣橱都重新发起慢请求，表现为「反复调用」。
4. 提示词过长（system + user 双消息、重复 JSON 约束、衣橱名等无关字段），生成耗时与 token 消耗偏高。

**修复**：
- `cloudfunctions/emptyGuide/provider/hunyuan.js`：新增 25s 绝对硬超时（定时器 + `req.destroy()`）；Promise 统一经 `finish()` 落定并清理定时器，任何分支必定返回；补 `res.on('error')` / `res.on('aborted')` 监听；`https.Agent({ keepAlive: true })` 复用连接，减少热启动重复建连开销。
- 提示词精简：合并为单条 user 消息，去掉冗余说明与衣橱名，模板改为「穿搭顾问。{性别}，{年龄}岁，衣橱为空。天气{现象 温度}。给1条≤50字的入门单品建议，侧重{年龄风格}。只输出JSON：{"tips":["建议"]}」；样例约 73 字（原 system + user 约 258 字，字符数降约 72%），性别/年龄/天气/输出格式信息不丢。
- `cloudfunctions/emptyGuide/index.js`：兜底结果缓存 10 分钟（成功仍 24 小时），失败日志带耗时；移除未使用的 `wardrobeName` 归一化。

**验证**：`node cloudfunctions/emptyGuide/test/index.local.test.js` **9/9 通过**。

#### 问题 4：直连 github.com 失败，经本地代理推送成功

- **现象**：`git push` 两次失败，无法直连 GitHub。
- **错误代码 / 内容**：

```text
fatal: unable to access 'https://github.com/goldme2003/LaoDengWardrobe.git/': Recv failure: Connection was reset
```
