## 1. 数据库基本信息

| 项目 | 内容 |
| --- | --- |
| 数据库名称 | `ldw_data_v1`（本地存储键，键名后缀 `v1` 为数据结构版本号） |
| 数据库类型 | 键值存储（单 JSON 文档，内含全部逻辑集合） |
| 存储引擎 | 微信小程序本地缓存，经 Taro 同步 API 访问（`Taro.getStorageSync` / `Taro.setStorageSync`） |
| 地址 | 无（数据保存在用户设备本地，无网络服务） |
| 端口 | 无 |
| 访问层代码 | `src/store/useWardrobeStore.ts`（zustand 状态 + 存储持久化） |
| 容量限制 | 微信本地缓存：单 key ≤ 1MB，全部 key 合计 ≤ 10MB |
| 登录/网络 | MVP 阶段无登录、无同步；唯一网络请求为天气数据获取 |

> 说明：MVP 阶段按 PRD 6.3 采用「先本地后云端」策略，存储访问层与业务解耦，后续版本引入微信登录与云端存储时可整体替换实现。届时本文档需补充云端数据库的地址、端口、鉴权方式等信息。

## 2. 集合（表）清单

`ldw_data_v1` 单文档内包含以下逻辑集合：

| 集合 | 说明 |
| --- | --- |
| `wardrobes` | 衣橱（一位用户/家人的独立衣物集合） |
| `items` | 衣物条目（隶属某个衣橱） |
| `tryoutItems` | 备选条目（准备购入的试穿/展示信息，v0.5 新增） |
| `customOptions` | 用户自定义属性选项（类型/颜色/材质/尺码/场合） |
| `counters` | 衣物命名流水号计数器 |
| `bodyProfiles` | 个人身体数据（v0.6 起按衣橱归属，key = 衣橱id，切换衣橱联动；旧版全局 `bodyProfile` 已迁移） |
| `favoriteBrands` | 喜爱品牌列表（v0.5 新增） |
| `diaryEntries` | 着装日记（v0.6 新增，按日期记录当天着装照片） |
| `tomorrowOutfits` | 明日穿搭勾选（v0.6 新增，key = 衣橱id，value = 衣物id 数组） |
| `city` | 天气城市（空 = 未选择） |
| `currentWardrobeId` | 当前选中衣橱 id |

> 运行时字段 `wardrobeFilterPreset`（首页待应用筛选预设）不持久化，每次写入存储时恒为 null。

## 3. 表结构

### 3.1 `wardrobes`（衣橱）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键，`genId()` 生成 |
| `name` | string ≤10 字 | 是 | 用户名称（衣橱标识），创建后不可修改，不可重名 |
| `color` | string | 是 | 主题色（取自所选风格主题主色，如 `#B07D50`） |
| `gender` | `'male' \| 'female'` | 是 | 衣橱主人性别（v0.5） |
| `age` | number \| null | 否 | 衣橱主人年龄，null = 未填写（v0.5） |
| `themeId` | `'warm' \| 'ocean' \| 'mint' \| 'honey' \| 'rose' \| 'ink'` | 是 | 风格主题（v0.5） |
| `createdAt` | number | 是 | 创建时间（epoch 毫秒） |

### 3.2 `items`（衣物条目）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `wardrobeId` | string | 是 | 外键 → `wardrobes.id` |
| `photos` | string[]（1–9） | 是 | 照片组（本地文件路径），第 1 张为主图 |
| `name` | string | 是 | 系统按「用户-服装类型-编号」自动命名，允许手动修改 |
| `renamed` | boolean | 是 | 用户是否手动改过名（改名后名称不再随类型联动） |
| `type` | string | 是 | 服装类型（预设或自定义） |
| `layer` | string | 是 | 内外穿：`内穿 / 外穿` |
| `color` | string | 是 | 颜色（预设或自定义） |
| `material` | string | 是 | 材质（预设或自定义） |
| `seasons` | string[]（1–4） | 是 | 穿着季节：`春 / 夏 / 秋 / 冬` |
| `size` | string | 否 | 尺码（XS–XXL 或自定义），可空字符串 |
| `brand` | string ≤20 字 | 否 | 品牌，可空字符串 |
| `occasions` | string[] | 否 | 适用场合：日常/通勤/运动/正式/居家/旅行 |
| `purchase` | object | 否 | 购入信息（v0.5），子字段：`date`（YYYY-MM-DD）、`place`、`price`（元）、`photo`（凭证照片路径） |
| `favorite` | boolean | 是 | 喜爱标记，默认 false |
| `remark` | string ≤200 字 | 否 | 备注 |
| `createdAt` | number | 是 | 录入时间（epoch 毫秒），列表按此倒序 |

### 3.3 `tryoutItems`（备选条目，v0.5）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `wardrobeId` | string | 是 | 外键 → `wardrobes.id` |
| `photos` | string[] | 是 | 试穿/展示图片（本地文件路径） |
| `name` | string | 是 | 备选名称（默认「未命名备选」） |
| `type` | string | 否 | 期望服装类型（转正式衣物时预填） |
| `color` | string | 否 | 颜色 |
| `brand` | string | 否 | 品牌 |
| `size` | string | 否 | 尺码 |
| `price` | string | 否 | 期望价格（元） |
| `note` | string | 否 | 试穿感受/备注 |
| `createdAt` | number | 是 | 创建时间（epoch 毫秒） |

### 3.4 `customOptions`（自定义属性选项）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `dimension` | `'type' \| 'color' \| 'material' \| 'size' \| 'occasion'` | 是 | 所属维度 |
| `value` | string | 是 | 选项文本（长度上限按维度：类型 10 / 颜色 6 / 材质 10 / 尺码、场合见 `CUSTOM_MAX_LEN`） |

约束：`dimension + value` 联合唯一；已被任一衣物使用的自定义选项不可删除。

### 3.5 `counters`（命名流水号计数器）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 键 | string | `${wardrobeId}__${服装类型}` |
| 值 | number | 该衣橱该类型下已分配的最大编号（001 起递增，删除不回收） |

### 3.6 `bodyProfiles`（个人身体数据，v0.6）

键值表：`Record<衣橱id, BodyProfile>`，每位衣橱主人一份，切换衣橱联动；全部字段选填（number，缺失即未填写）：

| 字段 | 单位 | 说明 |
| --- | --- | --- |
| `height` | cm | 身高 |
| `weight` | kg | 体重 |
| `bust` | cm | 胸围 |
| `waist` | cm | 腰围 |
| `hip` | cm | 臀围 |
| `shoulderWidth` | cm | 肩宽 |
| `shoulder` | cm | 肩围 |
| `armSpan` | cm | 臂展 |
| `neck` | cm | 领围 |
| `inseam` | cm | 裤长 |
| `thigh` | cm | 腿围 |
| `footLength` | mm | 脚长（鞋码参考） |

> v0.6 变更：由全局 1 份（`bodyProfile`）改为按衣橱归属（`bodyProfiles`）；读取旧数据时自动将旧全局数据迁移到当前衣橱名下。

### 3.7 `diaryEntries`（着装日记，v0.6）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `wardrobeId` | string | 是 | 外键 → `wardrobes.id` |
| `date` | string | 是 | 日期 YYYY-MM-DD（同一天可有多条记录） |
| `photos` | string[]（1–9） | 是 | 当天着装照片（本地文件路径） |
| `createdAt` | number | 是 | 记录时间（epoch 毫秒） |

### 3.8 `tomorrowOutfits`（明日穿搭勾选，v0.6）

键值表：`Record<衣橱id, string[]>`，值为勾选的衣物 id 数组（点击切换勾选状态；衣物删除后展示端自行过滤失效 id）。

### 3.9 `favoriteBrands`（喜爱品牌，v0.5）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| — | string[] | 品牌名字符串数组，品牌下拉中前置展示 |

### 3.10 其他标量

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `city` | string | 天气城市，空串 = 未选择 |
| `currentWardrobeId` | string | 当前选中衣橱 id → `wardrobes.id` |

## 4. 表关系

```text
wardrobes (1) ──< (N) items          items.wardrobeId → wardrobes.id（删除衣橱时级联删除）
wardrobes (1) ──< (N) tryoutItems    tryoutItems.wardrobeId → wardrobes.id（删除衣橱时级联删除）
wardrobes (1) ──< (N) diaryEntries   diaryEntries.wardrobeId → wardrobes.id（删除衣橱时级联删除，v0.6）
wardrobes (1) ──< (N) counters       counters 键内嵌 wardrobeId（删除衣橱时清理对应键）
wardrobes (1) ── (1) bodyProfiles    bodyProfiles[wardrobeId]（v0.6，删除衣橱时清理对应键）
wardrobes (1) ── (1) tomorrowOutfits tomorrowOutfits[wardrobeId]（v0.6，删除衣橱时清理对应键）
favoriteBrands / city / currentWardrobeId   全局标量，无外键
```

- 删除衣橱级联：删除 `wardrobes` 记录时，同步删除其下全部 `items`、`tryoutItems`、`diaryEntries`，清理 `counters`、`bodyProfiles`、`tomorrowOutfits` 中的对应键；最后一个衣橱不可删除。
- 命名联动：`items.name` 由 `wardrobes.name` + `type` + `counters` 流水号生成；`wardrobes.name` 创建后不可修改，保证已生成名称不失来源。

## 5. 版本与迁移

1. 存储键 `ldw_data_v1` 后缀 `v1` 为数据结构版本号；发生不兼容结构变更时递增键版本或编写迁移逻辑。
2. 现有迁移逻辑位于 `loadData()` / `migrateWardrobe()`：读取旧数据时补齐 v0.3 主题色字段与 v0.5 新字段（`gender` / `age` / `favoriteBrands` / `tryoutItems`）；v0.6 新增迁移：旧全局 `bodyProfile` 归属到当前衣橱（`bodyProfiles[currentWardrobeId]`），并补齐 `diaryEntries` / `tomorrowOutfits` 默认值。
3. 每次结构变更必须：更新本文件并递增文档版本号 → 提交推送 GitHub（见文首维护规则）。
