| 项目 | 内容 |
| --- | --- |
| 产品名称 | 老登衣柜 |
| 目标平台 | 微信小程序 |
| 文档版本 | v0.2（评审修订版） |

**v0.2 修订摘要**：① 照片由单张改为 1–9 张照片组；② 属性改为控件选择（下拉/勾选）并支持自定义选项，新增服装类型与内外穿属性；③ 新增多衣橱（家人/他人）；④ 新增内嵌天气预报；⑤ 新增喜爱标记；⑥ 新增备注；⑦ 着装日记移至后续版本；⑧ 命名规则改为「用户-服装类型-编号」。

## 1. 背景与目标

个人及家庭成员的衣物照片、类型、颜色、材质、季节属性分散在记忆和相册中，用户在穿搭决策（如「今天降温，找一件深色的冬季外套」）时无法快速定位衣物，也难以了解自己与家人各拥有什么。

老登衣柜是一个面向个人的衣物管理微信小程序：用户可以为多位家庭成员分别建立衣橱，通过拍照组快速记录衣物，为衣物标注服装类型、内外穿、颜色、材质、季节等属性与备注；并可以按这些维度浏览、筛选，结合内嵌天气预报辅助当日穿搭选择。

**可观察的产品结果**：用户在 1–2 分钟内可以完成一件衣物的拍照录入（照片组 + 属性选择）；录入后，用户可以按服装类型、颜色、材质、季节、喜爱任一维度筛选某位用户的衣物并查看详情；首页可以看到当日天气，作为穿搭参考。

## 2. 范围

### 2.1 MVP 范围（P0）

最小完整旅程：**建立衣橱 → 拍照/选图（照片组）→ 选择属性 → 保存 → 按维度筛选查看 → 查看详情 → 喜爱/编辑/删除**。

| 编号 | 能力 | 说明 |
| --- | --- | --- |
| FR-01 | 衣橱管理 | 新建/切换/删除衣橱（自己、家人、他人各一个衣橱） |
| FR-02 | 照片组录入 | 拍摄或从相册选择 1–9 张照片作为一组衣物照片 |
| FR-03 | 衣物属性编辑 | 通过下拉/勾选控件设置服装类型、内外穿、颜色、材质、季节；支持新增自定义选项 |
| FR-04 | 喜爱标记 | 标注/取消喜爱，支持「只看喜爱」筛选 |
| FR-05 | 备注 | 记录清洗方法、衣物来源、购买渠道等自由文本 |
| FR-06 | 衣柜列表与分类筛选 | 当前衣橱内衣物总列表 + 多维度筛选 |
| FR-07 | 衣物详情查看 | 查看照片组与全部属性 |
| FR-08 | 衣物删除 | 删除前确认 |
| FR-09 | 天气预报 | 首页内嵌当前城市天气展示 |

### 2.2 P1（本版不做，作为后续版本迭代）

- **着装日记**（需求待细化）：按日期选择某天，记录当日实际穿着的衣物，并可列出历史某天的穿着；与衣柜中的衣物条目关联。该功能产品方案尚未成熟，待 MVP 上线后另行细化评审。
- 云端同步与微信登录（见 6.3：MVP 为本地存储，存储层设计保证未来可替换为云端）。
- 照片拖拽排序、数据导出/备份。

### 2.3 排除项

- 社交、分享、电商、比价、二手交易；
- 洗护/保养提醒；
- AI 自动识别颜色、材质、品类（属性由用户手动选择）。

## 3. 产品模型

### 3.1 核心对象

**衣橱（Wardrobe）**：一位用户的独立衣物集合。

| 字段 | 说明 |
| --- | --- |
| 用户名称 | 衣橱标识（即命名规则中的「用户」，如「老登」），创建后不可修改 |
| 创建时间 | 系统记录 |
| 衣物条目 | 隶属于该衣橱的衣物列表 |

**衣物条目（Item）**：隶属于某个衣橱的单件衣物。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 照片组 | 图片 1–9 张 | 是 | 第 1 张为列表展示主图；来源为拍摄或相册 |
| 名称 | 文本 | 自动 | 系统按「用户-服装类型-编号」自动生成（见 6.2），允许用户修改 |
| 服装类型 | 单选 | 是 | 预设项 + 自定义项（见 6.1），如上装、裤装 |
| 内外穿 | 单选 | 是 | 内穿 / 外穿（固定枚举） |
| 颜色 | 单选 | 是 | 预设项 + 自定义项 |
| 材质 | 单选 | 是 | 预设项 + 自定义项 |
| 季节 | 多选（1–4 项） | 是 | 春 / 夏 / 秋 / 冬（固定枚举） |
| 喜爱 | 布尔 | 否 | 默认「否」，用户可随时切换 |
| 备注 | 多行文本 ≤200 字 | 否 | 清洗方法、衣物来源、购买渠道等 |
| 录入时间 | 系统记录 | — | 用户不可编辑 |

- 除照片组外的必填属性（服装类型、内外穿、颜色、材质、季节）在保存时校验：任一为空则无法保存，并高亮提示对应字段。
- 列表按录入时间倒序展示。

### 3.2 状态

- **衣橱**：正常 / 已删除。删除衣橱连带删除其下全部衣物（见 FR-01）。
- **衣物条目**：正常 / 已删除。已删除条目不出现于任何列表与筛选结果；MVP 无回收站，删除即最终生效（删除前确认见 FR-08）。

## 4. 核心流程

```text
【衣橱】首次打开 → 自动创建「我的」衣橱 → 可新建其他衣橱（家人/他人）并随时切换

【录入】在当前衣橱下点击"添加衣物" → 拍照/相册选择获得 1–9 张照片
        → 依次选择 服装类型/内外穿/颜色/材质/季节（均必填，可新增自定义选项）
        → 填写备注（可跳过）→ 保存 → 系统自动命名，新衣物置顶

【查看】浏览当前衣橱列表（全部 或 按类型/颜色/材质/季节/喜爱筛选）
        → 点击衣物 → 查看照片组与属性详情 → 喜爱/编辑/删除

【天气】进入首页 → 自动展示当前城市今日及未来 3 日天气 → 穿搭参考
```

## 5. 功能需求

### FR-01 衣橱管理

**目的**：为不同的人（自己、家人、他人）分别管理衣物，互不混淆。

**触发**：进入小程序首页；点击首页顶部的衣橱切换器。

**处理规则**：

1. 首次使用自动创建默认衣橱，用户名称为「我的」。
2. **新建衣橱**：在衣橱管理面板输入用户名称（≤10 字，不可与现有衣橱重名）后创建；创建成功后自动切换到新衣橱。
3. **切换衣橱**：通过首页衣橱切换器选择；切换后列表、筛选、添加衣物均针对所选衣橱。
4. **删除衣橱**：在衣橱管理面板删除；弹窗确认「将同时删除该衣橱下全部衣物，不可恢复」；确认后连带删除其下全部衣物与照片数据。至少保留 1 个衣橱，最后一个衣橱不可删除。
5. 衣橱名称创建后不可修改（避免已生成的衣物命名失去来源）。

**例外**：输入重名或超长时，即时提示并阻止创建。

### FR-02 照片组录入

**目的**：用一组照片完整记录一件衣物（整体、细节、标签等）。

**触发**：在当前衣橱下点击「添加衣物」。

**处理规则**：

1. **拍照**：调起微信相机，每次拍摄 1 张并加入照片组；可连续拍摄多张。
2. **相册选择**：调起微信相册选择器，单次最多选择「9 − 已选张数」张。
3. 照片组总数上限 9 张；达到上限后隐藏添加入口并提示。
4. 获得至少 1 张照片后进入属性编辑页（FR-03）；照片组展示于编辑页顶部，第 1 张为主图。
5. 编辑页提供「设为主图」：将组内任一照片设为主图（与其余照片交换位置）。
6. 提供删除组内照片入口，剩余至少 1 张；删除到 0 张时返回衣柜页，不产生条目。
7. 照片以小程序可展示的格式与适中分辨率保存（压缩策略为技术实现，不在本文档定义）。

**例外**：

| 场景 | 行为 |
| --- | --- |
| 拒绝相机/相册权限授权 | 展示引导文案，提示去设置页开启授权；提供拍照与相册两种入口重试 |
| 拍摄/选择中途取消 | 未获得任何照片时返回衣柜页，不产生条目 |

### FR-03 衣物属性编辑

**目的**：通过标准化控件为衣物建立可筛选的属性档案。

**触发**：FR-02 照片组获取成功后（新录入）；或在详情页点击「编辑」。

**处理规则**：

1. 编辑页顶部为照片组（见 FR-02 第 5–6 条）。
2. 属性控件：

| 字段 | 控件 | 选项来源 |
| --- | --- | --- |
| 服装类型 | 下拉单选 | 预设 + 自定义 |
| 内外穿 | 下拉单选 | 固定：内穿 / 外穿 |
| 颜色 | 下拉单选 | 预设 + 自定义 |
| 材质 | 下拉单选 | 预设 + 自定义 |
| 季节 | 勾选多选（1–4 项） | 固定：春 / 夏 / 秋 / 冬 |

3. **自定义选项**：服装类型、颜色、材质三个维度在选项面板底部提供「+ 新增选项」入口；输入文本（服装类型 ≤10 字，颜色 ≤6 字，材质 ≤10 字）确认后立即加入该维度选项列表并默认选中当前衣物（规则见 6.1）。
4. **保存**：五个必填属性全部已选且照片组 ≥1 张时方可保存；未满足时「保存」置灰或点击后高亮缺失字段。保存后返回列表，新条目置顶（按录入时间倒序）。
5. 名称由系统自动生成（见 6.2），编辑页展示名称预览；提供「修改名称」入口，允许用户手动改名（改名只影响该条目，不影响编号分配）。
6. **备注**：多行文本框，≤200 字，可跳过。
7. 编辑已有衣物时，保存覆盖对应字段；照片组可增删、可更换主图。

### FR-04 喜爱标记

**目的**：让用户快速标记并回找心爱衣物。

**处理规则**：

1. 详情页提供「喜爱」开关（心形图标），点击即切换喜爱/取消，即时生效，无需保存确认。
2. 列表条目上直接提供喜爱图标：点击切换；已喜爱条目显示实心心形。
3. 编辑页不提供喜爱开关（避免误改），喜爱仅在列表与详情操作。
4. 切换喜爱不改变条目的录入时间与排序位置。

### FR-05 备注

**目的**：记录结构化属性之外的自由信息。

**处理规则**：

1. 备注为多行自由文本，≤200 字，超出后输入框截断。
2. 内容由用户自行决定，常见用途：清洗方法、衣物来源、购买渠道等；产品不强制格式。
3. 备注在详情页完整展示；列表不展示备注。
4. 可留空；留空时详情页显示「未填写」。

### FR-06 衣柜列表与分类筛选

**目的**：在当前衣橱内按维度快速找到衣物。

**触发**：进入小程序首页（衣柜页），或操作筛选器。

**处理规则**：

1. **列表**：展示当前衣橱的全部衣物，按录入时间倒序；条目呈现「主图缩略 + 名称 + 喜爱图标 + 关键属性标签（服装类型/颜色/季节）」。
2. **筛选维度**：服装类型、颜色、材质（单选，含「全部」与「未设置」）、季节（多选并集，含「全部」与「未设置」）、喜爱（「只看喜爱」开关）。
3. 多维度叠加取交集；任一维度选「全部」表示该维度不限制。
4. 选项列表 = 预设项 + 已生效的自定义项（见 6.1）。
5. **空结果**：展示空态文案与「添加衣物」入口。
6. **空衣橱**：当前衣橱无衣物时展示引导页与「添加衣物」主按钮。
7. 顶部展示衣橱切换器与「添加衣物」按钮；天气卡片位于列表上方（见 FR-09）。

**例外**：自定义选项较多时选项面板支持纵向滚动，不设数量上限。

### FR-07 衣物详情查看

**目的**：查看单件衣物的完整信息。

**触发**：在列表中点击任一衣物条目。

**处理规则**：

1. 展示照片组（可左右滑动浏览，主图居首）与全部属性：名称、服装类型、内外穿、颜色、材质、季节、备注、录入时间。
2. 备注为空显示「未填写」；其余必填属性不会为空。
3. 提供操作入口：喜爱（FR-04）、编辑（FR-03）、删除（FR-08）。

### FR-08 衣物删除

**目的**：移除不再拥有的衣物。

**触发**：在详情页点击「删除」。

**处理规则**：

1. 弹窗确认：「删除后不可恢复，确定删除该衣物吗？」，提供「取消」与「删除」。
2. 确认后条目立即从所有列表与筛选结果中移除，并从本地存储清除照片与属性数据；该条目的编号不回收、不重排（见 6.2）。
3. 取消则无任何变更。

### FR-09 天气预报

**目的**：在衣柜场景内直接获取天气信息，辅助当日穿搭决策。

**触发**：进入小程序首页时自动加载。

**处理规则**：

1. 首页列表上方展示天气卡片，内容包含：城市名、今日天气现象、今日气温范围（最低–最高）、未来 3 日逐日简报（日期、天气现象、气温范围）。
2. 位置来源：请求微信定位授权，取当前城市；用户拒绝授权或定位失败时，提供手动选择城市入口（省/市选择），所选城市被记住，后续不再重复请求定位。
3. 天气卡片提供手动刷新；进入首页时自动刷新一次，刷新间隔不限频。
4. 天气信息仅为展示与参考，不参与任何筛选、推荐逻辑。

**例外**：

| 场景 | 行为 |
| --- | --- |
| 天气数据获取失败 | 卡片展示「天气获取失败」与重试按钮，不影响衣柜功能使用 |
| 定位授权被拒绝 | 提示可手动选择城市；不重复弹授权 |
| 天气服务不可用 | 同「获取失败」处理 |

## 6. 共享规则与例外

### 6.1 分类维度与自定义规则

**预设选项（MVP 初版，可在后续版本调整）：**

| 维度 | 预设选项 | 控件 | 自定义 |
| --- | --- | --- | --- |
| 服装类型 | 上装、裤装、裙装、连衣裙、外套、内衣、家居服、鞋履、配饰、其他 | 下拉单选 | 支持（≤10 字） |
| 内外穿 | 内穿、外穿 | 下拉单选 | 不支持 |
| 颜色 | 黑色、白色、灰色、红色、橙色、黄色、绿色、蓝色、紫色、粉色、棕色、米色、牛仔蓝 | 下拉单选 | 支持（≤6 字） |
| 材质 | 棉、麻、丝绸、羊毛、羊绒、涤纶、牛仔、皮革、羽绒、醋酸、其他 | 下拉单选 | 支持（≤10 字） |
| 季节 | 春、夏、秋、冬 | 勾选多选（1–4 项） | 不支持 |

**自定义规则（服装类型、颜色、材质适用）：**

1. 在对应维度选项面板底部提供「+ 新增选项」入口。
2. 输入文本确认后立即加入该维度选项列表，并在当前衣物的编辑中默认选中。
3. 自定义选项与预设选项在编辑、筛选、展示上完全同权。
4. 自定义选项一旦被任一衣物使用即不可删除；未被使用的自定义选项可在选项面板中删除。
5. 内外穿、季节为固定枚举，不支持自定义。

**必填规则**：服装类型、内外穿、颜色、材质、季节均为必填；保存时校验，缺失则阻止保存并高亮缺失字段。

### 6.2 命名规则

1. 衣物名称由系统按 **「用户-服装类型-编号」** 自动生成，例如「老登-上装-007」。
2. **用户** = 该衣物所属衣橱的用户名称（FR-01）。
3. **服装类型** = 该衣物当前的服装类型属性值；编辑修改服装类型时，名称中的类型随之更新（若用户未手动改名）。
4. **编号** = 同一衣橱内同一服装类型下的 3 位流水号（001 起，按录入顺序递增）；删除衣物后编号不回收、不重排。
5. 用户可在编辑页手动修改名称；改名后系统不再自动更新该条目名称，名称与编号的对应关系以名称文本为准。

### 6.3 存储规则（先本地后云端）

1. MVP 阶段所有数据（衣橱、衣物、照片组、属性、喜爱、备注）保存在用户设备本地，无需登录即可使用。
2. 多衣橱数据均存于本地，互不共享。
3. 数据结构与存储访问层的设计需保证：后续版本引入微信登录与云端存储时，可在不改变用户可见行为的前提下替换存储实现；本版不实现任何登录、同步界面或网络请求（天气数据获取除外）。
4. 卸载小程序或清除小程序数据会导致本地数据丢失；MVP 在「关于」页展示一次性数据提示文案，不提供导出功能。

### 6.4 权限

MVP 为单设备个人工具，无角色区分；仅使用微信小程序运行时要求的设备权限：相机、相册、定位（用于天气，见 FR-09）。
