## 1. 概述（Overview）

**目标**：将 PRD v1.10.0 中所有**未完成**的功能域（F-01～F-16 中未闭环部分，见 8.1 状态索引）转化为可排期、可验收的实施任务，按优先级分 5 个阶段（Phase 0～4）推进，最终使「老登衣柜」达到第 10 章各改造需求（R-1～R-7）的验收标准。

**当前基线**：v1.10.0（明日推荐档位缓存版）。F-17～F-21 已完成（会员体系、明日推荐次数缓存、下拉刷新定位等）；数据源层问题（华风爱科主源）已解决。

**已完成、不列入本计划**（引自 8.1，仅作追溯）：F-17 天气卡定位标识、F-18 城市切换联动、F-19 会员体系三档、F-20 下拉刷新定位、F-21 明日推荐次数与缓存。

### 3.2 关键非功能需求

- **性能**：推荐 AI 全链路 ≤5s（到达率 ≥90%）、本地首屏 ≤300ms / ≤1s、客户端硬超时 ≤8s（10.3）。
- **可靠性**：主源 Key 缺失自动降级不白屏（10.1）；照片集无网络不白屏（10.7）。
- **合规**：隐私合规声明 + 删除云端数据入口（10.5）；iOS 虚拟支付合规评估（10.6）；商用素材版权留存（10.7）。
- **一致性**：数据库结构变更须同步更新 `数据库开发文档`；代码升版联动 PRD/开发日志版本号（11.2）。

## 4. 技术方案（Technical Approach）

- **城市选择（R-1）**：复用现有 `src/data/cities.ts` 离线兜底 + 云函数 `weatherProxy action:'city'`（腾讯逆地理 / 华风爱科 lookup）；新增前端三级弹层组件与防抖搜索，数据结构沿用中国天气网编码表。
- **推荐提速（R-3）**：三层策略——① 前端本地优先渲染（规则引擎结果即时上屏）＋「衣橱版本+场景+天气签名」10 分钟缓存；② 云函数瘦身（衣物上限 20 件、max_tokens 收敛、理由 ≤120 字、模型超时 ≤6s）；③ 请求治理（场景/城市防抖 400ms、取消过期请求、客户端硬超时 8s）＋埋点 local_ready / ai_ready / ai_timeout。
- **出差完整版（R-2）**：新增出差计划数据结构（存 store，按衣橱 id 挂载），目的地城市复用 R-1 选择组件，打包清单件数按规则 `⌈天数÷换洗周期⌉` 计算，逐日穿搭前 3 天用真实预报、第 4 天起标注「预估」。
- **云同步（R-5）**：wx.login 静默登录 → 云数据库按 `updatedAt + 版本号` 增量上行；照片走云存储 + 缩略图缓存；冲突不静默覆盖、保留副本；同步状态可视化 + 失败重试；容量按会员档（entitlement.ts 扩展）。
- **照片集完整版（R-7）/ 趋势匹配（F-10）**：新建独立页面 + 云数据库内容集合（人工维护），与 9.2 趋势匹配共用关键词库；客户端 24 小时缓存、失败展示默认集；相似单品匹配复用现有筛选索引。
- **支付接入（R-6 剩余）**：恢复 `member.createOrder` → `cloud.cloudPay.unifiedOrder` + 支付回调 → 回调写 `members` 集合 → `getMember` 启动同步档位（服务端校验为准）；移除页内测试切换按钮组。

## 5. 实施阶段（Implementation Phases）

### Phase 0：待确认项澄清（阻塞项前置）

**目标（Goal）**：在开发前关闭所有规格歧义，避免返工；不写业务代码。

- [ ] **T0-01**（S）：确认 R1-Q1 城市粒度——到「市」还是「区县」（PRD 10.1.4，建议：到市）。产出：决策记录写入 PRD 10.1.4。
- [ ] **T0-02**（S）：确认 R1-Q2 高德备源本期不启用、R1-Q3 和风/华风额度口径（PRD 10.1.4）。产出：决策记录。
- [ ] **T0-03**（S）：确认 F-12 照片上限决策（PRD 7 Q-3）。产出：关闭开放问题或登记延期。
- [ ] **T0-04**（M）：iOS 虚拟支付合规评估（PRD 10.6 规则 5）——确认 VIP/SVIP 买断制在 iOS 端的展示策略（隐藏入口 / 引导 H5 / 暂不开放 iOS）。产出：合规结论写入 10.6。
- [ ] **T0-05**（S）：SVIP「综合衣橱深度推荐」字数与混元 token 成本核对（结合 10.3 max_tokens 收敛，避免两规格冲突）。产出：确认 100~150 字建议与 ≤120 字理由口径的适用边界。

**阶段验收**：全部决策回写 PRD 并推送；Phase 1 无阻塞开工。

### Phase 1：P0 核心（R-1 城市选择 + R-3 推荐提速）

**目标（Goal）**：解决两大 P0——「部分城市看不到天气」与「推荐生成过慢」，达到 10.1 / 10.3 验收标准。

#### T1-1 组：F-01 / R-1 前端城市选择与搜索（规格 10.1）

- [ ] **T1-01**（M）：城市选择弹层重构——「省 → 市 →（区县，视 T0-01 决策）」三级面板，支持返回上级；替换现「常用 15 城平铺」。
  - 验收：地级市抽样 30 个均能返回真实天气；层级切换流畅无白屏。
- [ ] **T1-02**（M）：关键词搜索——支持汉字与拼音首字母（如「杭州」「hz」），300ms 防抖，结果高亮当前城市。
  - 验收：搜索「杭州」「hz」均在 2 秒内返回并可选定。
- [ ] **T1-03**（M）：未覆盖城市体验——数据源无该城市时提示并推荐临近城市一键切换；离线兜底 `cities.ts` 编码表可用。
  - 验收：主源 Key 缺失或城市未覆盖时自动降级，页面不白屏、有明确提示。
- [ ] **T1-04**（S）：定位精度校验——逆地理返回城市与定位点天气交叉核对。
  - 验收：定位城市天气温度误差 ≤2℃。
- [ ] **T1-05**（S）：R-1 联调验收 + 留档（测试记录写入开发日志）。

#### T1-2 组：F-02 / R-3 推荐生成提速（规格 10.3）

- [ ] **T1-06**（M）：前端本地优先——规则引擎结果即时渲染（≤300ms），AI 返回后无缝替换；客户端硬超时 ≤8s，超时保留本地结果不转圈。
  - 验收：本地首屏 ≤300ms、完整首屏 ≤1s；超时场景无无限 loading。
- [ ] **T1-07**（M）：本地缓存——「衣橱版本 + 场景 + 天气签名」key，命中有效期 10 分钟；签名任一变化即失效。
  - 验收：10 分钟内重复进入（条件未变）命中缓存、不发起 AI 请求。
- [ ] **T1-08**（M）：请求治理——场景/城市切换 400ms 防抖，取消过期请求（丢弃陈旧响应，防止旧结果覆盖新结果）。
  - 验收：连续切换 5 次场景，实际发出 AI 请求 ≤2 次。
- [ ] **T1-09**（M）：云函数瘦身——`outfitRecommend` 入参衣物上限 20 件、max_tokens 收敛、理由 ≤120 字、模型侧超时 ≤6s（与 T0-05 结论对齐）。
  - 验收：云函数冷启动外的平均响应明显下降，配合前端达成 AI ≤5s。
- [ ] **T1-10**（S）：性能埋点——local_ready / ai_ready / ai_timeout 三事件上报（现有统计通道或云函数日志）。
  - 验收：可查到 AI ≤5s 到达率 ≥90% 的统计口径。
- [ ] **T1-11**（S）：R-3 整体验收留档（30s–1min → ≤5s 的前后对比写入开发日志）。

**阶段验收**：10.1 与 10.3 全部验收标准通过；`npm run build:weapp` + `npm run verify:sync` 通过；升版推送。

## 7. 风险与缓解（Risks & Mitigation）

| # | 风险 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| 1 | 决策项（T0-0x）迟迟未确认，阻塞 P0 开工 | 高 | Phase 1 中仅 T1-01 依赖 T0-01，其余提速任务可先行；决策项按默认建议（到市 / 不启用高德）推进并在 PRD 标注「默认决策、待复核」 |
| 2 | 混元响应时长不可控，≤5s 达标率难保 | 高 | 本地优先 + 硬超时 + 缓存三层兜底，AI 慢不阻塞用户；埋点持续监控达标率 |
| 3 | 云同步冲突场景复杂，副本策略实现成本高 | 中 | 先做单向增量上行（低风险）再补冲突副本；同步引擎拆小任务独立验收 |
| 4 | iOS 虚拟支付合规不确定 | 中 | T0-04 提前评估；最坏方案 iOS 隐藏开通入口（仅测试模式），不影响 Android |
| 5 | 照片集内容人工维护量大、断更 | 中 | 24h 缓存 + 默认集兜底；首版仅 1 季 6 组即可上线，后续按季补 |
| 6 | 批量导入识别准确率不达预期 | 中 | 必填三属性（类型/颜色/季节）失败时强制人工确认页兜底，不入库错误数据 |
| 7 | 多阶段并行导致版本号与文档失同步 | 低 | 严格按 11.2：每次升版联动 package.json / APP_VERSION / PRD / 开发日志；verify:sync 前置 |

## 8. 成功标准（Success Criteria）

1. **P0 达标**：地级市天气覆盖抽样 30/30 通过；推荐 AI 全链路 ≤5s 到达率 ≥90%（埋点口径），本地首屏 ≤1s。
2. **P1 达标**：出差计划按 10.2 件数规则验收通过；云同步四项验收（跨设备 ≤10s / 离线恢复上行 / 冲突副本 / 删除无残留）通过；推荐丰富度三要素齐全。
3. **P2 交付**：照片集每季 ≥6 组、每组 ≥3 套 look、无网络不白屏；批量导入上线并按会员额度门控。
4. **商业化闭环**：真实支付走通、档位服务端校验、测试模式移除、iOS 合规策略落地。
5. **过程达标**：所有验收留档于开发日志；数据库文档与 PRD 版本号全链路一致；全程未出现 verify:sync 不通过即提交的情况。
