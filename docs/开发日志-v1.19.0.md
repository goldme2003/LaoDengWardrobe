  - `MemberUsage` 新增 `dailyOutfitUsed: Record<衣橱id, 当日已生成套数>`；`initialUsage` 初始化；`rolledUsage` 跨天重置该计数。

  - `recordSeasonalView` / `recordTripUse` / `recordBatchImportUse` 去 `localOnly`（打脏 → 3s 防抖上行）；
  - `appendDailyOutfit` 同步维护 `memberUsage.dailyOutfitUsed`（推荐缓存本体仍仅本地）。
- `src/services/sync.ts`
  - 快照结构 `SnapshotData` 新增 `memberUsage`（全局，不按衣橱裁剪，构建时 `rolledUsage` 保证窗口新鲜）；
  - 合并规则：窗口（day/month）一致时各计数取 max（单调递增，防换端重复用额度），窗口不一致以本地为准（`mergeMemberUsage`）；`mergeSnapshot` 与 `applyRemoteOverwrite`（云端覆盖本地）均应用该规则，旧快照缺字段以 `rolledUsage` 兜底；
  - 单端互踢：新增设备标识（`ldw_device_id` 本地持久化），`login / pull / push / photoStat` 均携带 `deviceId`；新增同步状态 `'kicked'`——收到 `KICKED` 后清理防抖定时器、进入 kicked 态并 toast 提示，`syncOnce / schedulePush / uploadPendingPhotos` 均不再发起（kicked 不被 ready/error 覆盖）；「立即同步」在 kicked 态先重新登录接管（顶掉另一端）再同步。
- `src/pages/mine/index.tsx`
  - 同步状态条新增 kicked 文案：「账号已在其他设备登录，本机已暂停云同步（点「立即同步」重新接管）」。

### 遇到的问题与决策

- VIP 等级同步在 v1.17.0 已落地（服务端权威 + 会话内实时上行），本次未重复实现，仅保持口径。
- 「云端覆盖本地」冲突策略下用量计数若直接被覆盖会回退（换端少计数），故覆盖时用量计数单独走 max 合并，与编号计数器口径一致。
- 推荐缓存 `dailyOutfits` 仍不上云（设计方案 4.4），仅把「当日已生成套数」以 `dailyOutfitUsed` 计入用量上云，避免整套缓存跨端回放旧推荐。
