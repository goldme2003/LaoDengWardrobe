## 2. 腾讯位置服务开通与配置步骤（A 阶段前置）

### 2.1 账号与认证

1. 浏览器打开腾讯位置服务控制台 <https://lbs.qq.com/dev/console/application/mine>，使用**微信扫码**登录（推荐，便于与小程序主体对齐）。
2. 进入「控制台 → 账号中心 → 实名认证」，选择主体类型：
   - 个人：身份证 + 人脸核身；企业：营业执照 + 对公打款/法人认证。
   - 未实名无法创建 Key 与调用 WebServiceAPI。
3. 认证审核通过后，在「配额管理」确认免费额度（个人认证逆地址解析通常为 5000 次/日、QPS 5，**以控制台实际显示为准**）。

### 2.2 创建应用与 Key

1. 「控制台 → 应用管理 → 创建应用」，名称填 `老登衣柜`，类型选「微信小程序」。
2. 在应用下「添加 Key」，配置：
   - Key 名称：`laodeng-wardrobe-prod`
   - 启用产品：**WebServiceAPI**（逆地址解析 `geocoder`、地点搜索 `place`）
   - 绑定小程序 AppID：`wxe42fe1ecc2645be1`
   - 安全设置：填写服务器域名白名单（本项目走云函数调用，可不填；若后续前端直连需填 `apis.map.qq.com`），并妥善保存 **SK**（签名密钥，仅云函数使用）
3. 记录三项配置，写入云函数环境变量（**不写入前端、不提交仓库**）：

| 变量名 | 值来源 | 使用位置 |
| --- | --- | --- |
| `TENCENT_MAP_KEY` | 控制台 Key 列表 | `cloudfunctions/weatherProxy`（逆地理） |
| `TENCENT_MAP_SK` | Key 详情页（可选，仅签名校验时用） | 同上 |
| `QWEATHER_KEY` | 和风天气控制台 | 同上（天气数据） |

### 2.3 小程序侧域名与权限

1. 微信公众平台 →「开发管理 → 开发设置 → 服务器域名 → request 合法域名」：
   - 走云函数代理时**无需**添加（云函数不受域名限制），推荐此方式；
   - 若改为前端直连，需添加 `https://apis.map.qq.com`、`https://devapi.qweather.com`。
2. 「开发管理 → 接口设置」→ 申请「地理位置」接口（`wx.getLocation`），填写使用场景：「根据用户所在城市展示当日天气与穿衣推荐」，提交后等待审核（通常 1–2 个工作日）。
3. 「设置 → 基本设置 → 用户隐私保护指引」→ 勾选并填写「位置信息」用途，否则 2023 年后 `wx.getLocation` 会直接失败（隐私接口新规）。

### 2.4 定位能力配置（代码侧，A 阶段实施）

- `src/app.config.ts` 增加：

```ts
permission: {
  'scope.userLocation': { desc: '用于获取所在城市天气，为你推荐合适的穿搭' }
},
requiredPrivateInfos: ['getLocation']
```

- 授权流程：首次进入天气卡片 → 弹出自定义用途说明 → `Taro.getLocation({ type: 'gcj02' })` → 云函数逆地理 → 城市名；
- 拒绝授权：回退城市选择（省市级联），选择结果本地持久化，作为默认城市；不重复弹授权框，提供「去设置」入口。

### 2.5 天气数据源说明（修正 9.4 选型）

腾讯位置服务**只提供定位与逆地理**，不提供天气数据。天气按以下口径落地：

| 用途 | 服务 | 说明 |
| --- | --- | --- |
| 定位 / 逆地理 | 腾讯位置服务 WebServiceAPI | 本文档 2.1–2.4 |
| 天气数据（主） | 和风天气 QWeather | 免费 1000 次/日，实时 + 3 天预报，国内直连 |
| 天气数据（备） | 腾讯天气（非公开接口） | 不作为正式依赖，仅作参考 |

## 3. 功能设计

### 3.1 A 阶段：天气接入（`cloudfunctions/weatherProxy`）

| 项 | 设计 |
| --- | --- |
| 入参 | `{ action: 'city' \| 'weather', city?, lat?, lon? }` |
| 逆地理 | `GET https://apis.map.qq.com/ws/geocoder/v1/?location={lat},{lon}&key=...` → 取 `result.address_component.city` |
| 天气 | `GET https://devapi.qweather.com/v7/weather/3d?location={locationId}&key=...` |
| 归一化 | 输出既有 `WeatherInfo`：`{ city, today:{date,cond,low,high}, days[3] }`，现象映射为晴/多云/阴/小雨/中雨/大雨/雪/雾 |
| 缓存 | 集合 `weather_cache`，`_id = city + '-' + yyyyMMddHH`，TTL 30 分钟；命中不计费 |
| 限流 | 单用户 1 分钟最多 1 次真实请求 |
| 超时 | `config.json` 声明 `timeout: 20` |

### 3.2 B 阶段：推荐引擎（`src/services/recommend.ts`，纯函数 + 单测）

1. 输入：`WeatherInfo` + 当前衣橱衣物列表（类型、季节、内外穿、材质）；
2. 规则：按体感温度分档（<5 / 5–15 / 15–22 / 22–28 / >28℃）匹配品类与厚度，鞋履/外套按需增减；
3. 排序：季节匹配优先 → 近 30 天未穿优先（日记数据）→ 同类型取最近新增；
4. 输出：`{ items: ClothingItem[]; reason: string }[]`（1–3 套），`reason` 由模板生成，不调用大模型，保证 ≤2s 与可解释性；
5. 降级：天气不可用 / 衣物为空 → 不展示推荐卡片，不影响原有功能。

### 3.3 C 阶段：空衣橱专属引导（云函数 + 混元）

#### 3.3.1 触发条件

- 当前激活衣橱的衣物数量为 0；
- 衣柜页展示空态时调用（同一衣橱 + 同一性别/年龄 24 小时内只调用一次，命中本地缓存直接展示）；
- 网络失败/模型失败 → 展示内置兜底文案，不展示错误。

#### 3.3.2 云函数 `emptyGuide`

| 项 | 设计 |
| --- | --- |
| 入参 | `{ action: 'ping' \| 'guide', gender: 'male'\|'female'\|'other', age: number, wardrobeName?: string }` |
| 上下文 | 必传 `gender`、`age`（取自「我的」页个人资料，随衣橱主人联动）；缺参返回 `BAD_PARAM` |
| 提示词 | 系统：仅输出 JSON；用户模板：`你是一位专业穿搭顾问。用户性别：{gender}，年龄：{age} 岁，衣橱「{wardrobeName}」目前为空。请给出 2 条简短、具体、可执行的开启衣橱建议（每条 ≤40 字），并按年龄段调整语气与品类侧重（18 岁以下偏校园、18–30 偏通勤/休闲、31–50 偏通勤/质感、50 岁以上偏舒适/保暖）。输出 {"tips":["...","..."]}` |
| 输出 | `{ code:'OK', tips: string[], source:'hunyuan'\|'fallback' }` |
| 缓存 | 集合 `guide_cache`，`_id = md5(gender+age+wardrobeId)`，TTL 24 小时 |
| 降级 | 模型超时/鉴权失败/解析失败 → 返回按年龄性别挑选的内置文案（`source:'fallback'`，`code:'OK'`），前端无感 |
| 复用 | 复用 `recognizeClothing` 的混元 provider 与熔断/计数逻辑，避免重复封装 |

#### 3.3.3 前端展示

- 衣柜页空态区域：标题「这个衣橱还空着」+ 2 条动态建议 + 「去添加第一件」按钮；
- 文案区高度自适应、最多 2 行省略；加载中展示骨架，不阻塞添加操作；
- 埋点：`empty_guide_show` / `empty_guide_fallback` / `empty_guide_click_add`。

### 3.4 D 阶段：明日穿搭衔接

- 推荐卡片「一键采纳」写入 `tryout` 勾选数据；「换一件」按规则重排同类型候选；
- 所有写入保持现有数据结构，不新增字段。

## 4. 异常捕获与降级矩阵

| 场景 | 处理 | 用户可见 |
| --- | --- | --- |
| 定位授权拒绝 | 回退城市选择 | 正常展示所选城市天气 |
| 逆地理失败 | 使用上次城市缓存 → 默认城市 | 天气照常展示 |
| 天气接口失败/超限 | 云端旧快照 → 本地缓存 → 隐藏天气 | 不阻塞衣橱 |
| 云函数未部署/超时 | 前端 20s 硬超时 + 明确提示 | 提示「天气暂不可用」 |
| 混元 Key 缺失/超时 | 内置文案兜底 | 文案正常，无报错 |
| 性别/年龄缺失 | 使用默认值（other / 30）并记录告警 | 文案正常 |

## 5. 验收标准

1. 已授权定位：进入衣柜页 ≤3s 展示真实城市与真实天气；与官方天气对比温度误差 ≤2℃。
2. 拒绝定位：可通过城市列表切换，切换后数据正确刷新，无重复授权弹窗。
3. 空衣橱：展示 2 条含性别/年龄上下文的建议，且不同年龄段文案存在可辨识差异；模型故障时仍有兜底文案（`source: fallback`）。
4. 天气或模型任一侧故障时，衣橱主流程无报错、无白屏、无阻塞。
5. 缓存命中率 ≥90%（同城市 30 分钟内重复进入不重复计费）。
6. 全部用例纳入 `docs/测试方案-v1.2.1.md` 执行并留档。
