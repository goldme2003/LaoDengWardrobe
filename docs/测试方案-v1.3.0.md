## 2. 被测对象与链路概述

```
小程序「新增衣物」页 (src/pages/add/index.tsx)
  └─ 主图变化 800ms 防抖 / 点「重新识别」
      └─ recognizePhoto() (src/services/recognize.ts)
          ├─ 前置：RECOGNIZE_AVAILABLE（CLOUD_ENV_ID 已配置 && weapp 端）
          ├─ 前置：checkBudget() 熔断（≥50 元 exceeded / ≥40 元 warn）
          ├─ 前置：同图结果缓存（ldw_recognize_cache，≤20 条）
          ├─ 前置：首次隐私确认（拒绝 → PRIVACY_DENIED）
          ├─ Taro.cloud.uploadFile → cloud://recognize/时间戳_随机.jpg
          └─ Taro.cloud.callFunction('recognizeClothing', { imageFileID })
云函数 recognizeClothing (cloudfunctions/recognizeClothing/index.js)
  ├─ ① ping 探测 / BAD_PARAM 参数校验
  ├─ ② 熔断硬校验（数据库集合 recognize_usage，doc=usage_年-月）
  ├─ ③ 下载云存储图片 → base64
  ├─ ④ 混元视觉 (provider/hunyuan.js → tokenhub.tencentmaas.com/v1，模型 hy4)
  │      输出：isClothing / category / color / layer / season / hasTag /
  │            tagBrand / tagSize / tagText / confidence
  ├─ ⑤ 非衣物 → NO_CLOTHING
  ├─ ⑥ hasTag 时：腾讯云 OCR (provider/ocr.js，GeneralBasicOCR)
  │      └─ OCR 失败或密钥未配置 → 降级用混元读取的 tagText
  ├─ ⑦ 规则解析 (lib/parse.js)：成分/清洗/品类映射/材质映射/季节兜底/品牌/尺码
  │      置信度 <0.6 → category 置空不预填
  └─ ⑧ 用量计数 +1 → 返回 { code:'OK', data:attrs, cost, elapsed }
异常返回码：BAD_PARAM / BUDGET_EXCEEDED / NO_CLOTHING / NOT_CONFIGURED / RECOGNIZE_FAILED
```

## 5. 测试项明细

> 每条用例均含：测试场景 / 前置条件 / 测试步骤 / 预期结果 / 判定标准。

### A. 混元大模型调用链路测试（`provider/hunyuan.js` + `index.js`）

#### A1（P0）ping 连通性探测

- **测试场景**：验证云函数已部署、可调用、环境变量读取正常。
- **前置条件**：E1、E2 满足。
- **测试步骤**：
  1. 微信开发者工具「云函数」面板 → 选择 `recognizeClothing` → 本地/云端调试；
  2. 传入事件 `{ "action": "ping" }`，云端运行。
- **预期结果**：返回 `{ code: 'OK', hasSecret: <boolean>, budget: 50 }`。
- **判定标准**：`code === 'OK'`；且**注意**：当前 `ping` 的 `hasSecret` 仅检查 `TENCENT_SECRET_ID`，不反映 `HUNYUAN_API_KEY` 是否配置——本用例额外确认 `HUNYUAN_API_KEY` 已在环境变量中配置（若缺失会导致 A2 失败，属已知探测盲区，记录并评估是否改进 ping）。

#### A2（P0）混元视觉端到端调用（OpenAI 兼容端点）

- **测试场景**：验证 `tokenhub.tencentmaas.com/v1/chat/completions`（模型 hy4）真实可用、密钥有效。
- **前置条件**：A1 通过；`HUNYUAN_API_KEY` 已配置。
- **测试步骤**：
  1. 上传一张标准衣物测试照（素材 T-B1）至云存储，取得 fileID；
  2. 以 `{ "imageFileID": "<fileID>" }` 调用云函数；
  3. 观察云函数日志 `[recognize] 识别失败` 是否出现，检查返回 code。
- **预期结果**：返回 `code: 'OK'`，`data` 中各字段非空合理；`elapsed` 记录实测耗时。
- **判定标准**：无 `HUNYUAN_HTTP_*` / `HUNYUAN_TIMEOUT` / `HUNYUAN_BAD_JSON` / `BAD_MODEL_OUTPUT` 错误；耗时 ≤ 25s（请求超时上限）。

#### A3（P1）模型输出 JSON 解析健壮性

- **测试场景**：模型输出带 ```` ```json ```` 包裹或前后缀文字时，`text.match(/\{[\s\S]*\}/)` 能正确提取。
- **前置条件**：无需真实调用；本地 node 环境执行。
- **测试步骤**：
  1. 本地构造 mock 返回文本三份：纯 JSON、```` ```json\n{...}\n``` ```` 包裹、`识别结果：{...}` 前缀；
  2. 分别执行 `JSON.parse(text.match(/\{[\s\S]*\}/)[0])` 逻辑（或直接调用 mock 后的 `callHunyuanVision`）。
- **预期结果**：三份均解析成功且字段完整。
- **判定标准**：3/3 通过。

#### A4（P1）密钥未配置的错误路径

- **测试场景**：`HUNYUAN_API_KEY` 与本地 `private.config.json` 均缺失时抛 `MISSING_SECRET`。
- **前置条件**：临时移除密钥（测试环境）。
- **测试步骤**：调用云函数（真实图片 fileID），观察返回。
- **预期结果**：返回 `{ code: 'NOT_CONFIGURED', message: '识别服务未配置，请联系维护者' }`。
- **判定标准**：code 严格等于 `NOT_CONFIGURED`（而非笼统的 `RECOGNIZE_FAILED`）；测试后恢复密钥。

#### A5（P2）网络超时与 HTTP 非 200 处理

- **测试场景**：混元端点超时（>25s）或返回 4xx/5xx 时，异常被捕获并转为 `RECOGNIZE_FAILED`。
- **前置条件**：可通过临时改错 `HUNYUAN_MODEL`（触发 4xx）模拟；超时场景可临时将 timeout 调小后恢复。
- **测试步骤**：注入错误模型名 → 调用 → 观察日志与返回码 → 恢复配置。
- **预期结果**：返回 `code: 'RECOGNIZE_FAILED'`，日志含 `HUNYUAN_HTTP_4xx` 明细。
- **判定标准**：不产生未捕获异常（云函数不崩溃），返回码正确；配置已恢复。

#### A6（P1）请求体合规性（视觉消息结构）

- **测试场景**：发给混元的 messages 为 `[{ role:'user', content:[{type:'text'},{type:'image_url', image_url:{url:'data:image/jpeg;base64,...'}}] }]`，temperature=0.1。
- **前置条件**：A2 抓包/日志能力，或本地单测拦截 https.request。
- **测试步骤**：本地以桩替换 `https.request`，断言请求体结构。
- **预期结果**：结构与上述一致；base64 无 `data:` 前缀重复拼接。
- **判定标准**：断言全部通过。

### B. 衣物颜色识别准确性测试（混元 `color` 字段 → 前端颜色控件）

#### B1（P1）常见标准色识别

- **测试场景**：主体色为预设色（黑色/白色/灰色/红色/蓝色/绿色/黄色/粉色/米白/藏青等，取 `COLOR_PRESETS` 覆盖范围）的衣物照。
- **前置条件**：A2 通过；素材 T-B1×N（每种颜色 1 张，光照正常、主体占画面 ≥ 60%）。
- **测试步骤**：逐张上传识别，记录返回 `data.color` 与 `data.confidence`。
- **预期结果**：`color` 为中文颜色名（2–4 字），与照片主体色一致（如黑色卫衣 → 「黑色」）。
- **判定标准**：**准确率 ≥ 85%**（12 张标准色照允许 ≤ 1 张偏差）；`color` 长度 ≤ 6 字（`slice(0,6)` 截断生效）。

#### B2（P1）复杂色 / 非预设色识别

- **测试场景**：驼色、雾霾蓝、燕麦色等非预设中间色。
- **测试步骤**：同 B1 流程。
- **预期结果**：返回接近的颜色名（如「驼色」「米色」）。
- **判定标准**：语义接近即可判定通过（允许与预设不一致，前端支持自定义颜色）；记录偏差样例。

#### B3（P2）多色 / 图案衣物

- **测试场景**：条纹、印花、拼色衣物。
- **预期结果**：返回主色调。
- **判定标准**：主色调合理即通过；结果记入记录表（该类不设硬性指标）。

#### B4（P2）光照与拍摄条件鲁棒性

- **测试场景**：弱光、逆光、强反光三种条件下同一件衣物。
- **预期结果**：颜色不严重失真（黑色不识别为白色级别）。
- **判定标准**：3 张中 ≥ 2 张颜色语义正确。

### C. 衣物品类识别准确性测试（混元 `category` → `mapCategory` 映射）

#### C1（P1）十大预设品类直接命中

- **测试场景**：照片品类词与 `TYPE_PRESETS` 完全一致（上装/裤装/裙装/连衣裙/外套/内衣/家居服/鞋履/配饰/其他）。
- **前置条件**：素材 T-C1×N（每品类 ≥ 1 张）。
- **测试步骤**：逐张识别，记录 `data.category`。
- **预期结果**：`category` 等于预设词。
- **判定标准**：**准确率 ≥ 80%**；`category` 必须属于 `TYPE_PRESETS` 集合（映射层保证）。

#### C2（P1）细类名归一化映射

- **测试场景**：模型返回细类名（卫衣/衬衫/T恤→上装；羽绒服/夹克→外套；牛仔裤/运动裤→裤装；运动鞋/靴→鞋履；帽子/围巾→配饰 等，覆盖 `mapCategory` 9 条规则）。
- **测试步骤**：真实识别后核对映射结果（若模型直接返回细类名，则验证映射表生效）。
- **预期结果**：细类名正确归一到对应预设。
- **判定标准**：规则表内 9 类映射 100% 正确（可与 G2 单测合并执行）。

#### C3（P0）置信度过滤：低置信度不预填品类

- **测试场景**：模糊、遮挡、远距离拍摄衣物（预期模型 confidence < 0.6）。
- **测试步骤**：识别后检查返回 `data.category` 与 `data.confidence`、`data.warnings`。
- **预期结果**：`confidence < 0.6` 时 `category === ''`（云函数 index.js 第 108–109 行逻辑），warnings 含「品类置信度较低…」。
- **判定标准**：`category` 为空串且 warnings 非空；前端服装类型控件保持未选中状态（联动 F4）。

#### C4（P0）非衣物图片误报率

- **测试场景**：非衣物照片（风景、人物自拍、餐食、纯色背景、宠物）。
- **前置条件**：素材 T-C4×N（≥ 20 张干扰图）。
- **测试步骤**：逐张识别，记录 `code`。
- **预期结果**：返回 `code: 'NO_CLOTHING'`（isClothing=false）。
- **判定标准**：**误报率 ≤ 5%**（开发计划验收标准）；即 ≥ 19/20 张正确拒绝。

### D. 吊牌文字 OCR 识别准确性测试（`provider/ocr.js` + 降级链路）

#### D1（P0）清晰吊牌 OCR 主链路（CAM 密钥就绪）

- **测试场景**：吊牌正面平整特写（含品牌、尺码、面料成分如「60%棉 40%聚酯纤维」、清洗说明）。
- **前置条件**：E3 中 `TENCENT_SECRET_ID/KEY` 已配置；素材 T-D1×N（≥ 5 张不同品牌吊牌）。
- **测试步骤**：识别后检查 `ocrCalls` 计数 +1、`compositionText`、`careText`、`brand`、`size`。
- **预期结果**：`compositionText` 形如 `60%棉 40%聚酯纤维`；`careText` 含关键词标签（如 `可机洗；不可漂白`）；`brand`/`size` 与吊牌一致。
- **判定标准**：成分抽取正确率 ≥ 90%；清洗说明命中关键词 ≥ 2 项/张；`ocrUsed` 计数正确。

#### D2（P1）成分正则覆盖（「60%棉」「棉60%」「聚酯纤维/涤纶」多种写法）

- **测试场景**：吊牌成分的不同排版（比例前后、无比例仅成分词、含「氨纶 5%」混纺）。
- **预期结果**：`extractComposition` 抽出全部成分对；无比例时抽取成分关键词（≤ 3 个）。
- **判定标准**：正则两分支（名称在前/在后）均命中；可由 G3 单测覆盖。

#### D3（P1）OCR 失败降级链路（混元 tagText 兜底）

- **测试场景**：hasTag=true 但 OCR 调用失败（密钥错误 / 服务异常）。
- **前置条件**：`TENCENT_SECRET_ID` 故意配错（测试后恢复）。
- **测试步骤**：识别含吊牌照片 → 检查日志「OCR 失败，降级用模型读取的吊牌文字」及返回字段。
- **预期结果**：`ocrText` 回退为 `vision.tagText`，`compositionText`/`careText` 仍可产出；`ocrCalls` 计数 +0。
- **判定标准**：链路不中断、返回 `OK`；降级日志存在；计数正确。

#### D4（P2）水洗唛（缝在衣物内侧）文字识别

- **测试场景**：水洗唛特写（字体小、行密）。
- **预期结果**：至少抽出成分与一个清洗关键词。
- **判定标准**：5 张中 ≥ 4 张抽出成分信息。

#### D5（P1）hasTag=true 但文字提取完全失败

- **测试场景**：吊牌反光严重 / 字迹模糊，OCR 与 tagText 均为空。
- **预期结果**：warnings 含「检测到吊牌但文字提取失败，建议拍平整的吊牌正面」；`category/color` 等视觉字段正常返回。
- **判定标准**：warnings 命中该文案；不阻塞 OK 返回。

### E. 接口返回结果格式与正确性测试（`index.js` 出参契约）

#### E1（P0）OK 成功返回结构

- **测试步骤**：标准衣物照正常识别。
- **预期结果**：返回顶层字段 `code / data / cost / elapsed`；`data` 含 `category,color,layer,seasons,material,size,brand,careText,compositionText,confidence,warnings`（及可选 `remarkExtra`）；`cost = { calls: 递增, estCost: calls*0.06, budget: 50 }`。
- **判定标准**：字段齐全、类型正确（seasons 为数组、confidence 为数值、warnings 为字符串数组）；`recognize_usage` doc `calls` 与返回 `cost.calls` 一致。

#### E2（P0）BAD_PARAM 参数校验

- **测试步骤**：以 `{}`（缺 imageFileID）调用。
- **预期结果**：`{ code: 'BAD_PARAM', message: '缺少 imageFileID' }`；**不消耗**用量计数。
