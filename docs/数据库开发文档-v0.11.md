## 1. 数据库基本信息

| 项目 | 内容 |
| --- | --- |
| 数据库名称 | `ldw_data_v1`（本地存储键，键名后缀 `v1` 为数据结构版本号） |
| 数据库类型 | 键值存储（单 JSON 文档，内含全部逻辑集合） |
| 存储引擎 | 微信小程序本地缓存，经 Taro 同步 API 访问（`Taro.getStorageSync` / `Taro.setStorageSync`） |
| 地址 | 无（数据保存在用户设备本地，无网络服务） |
| 端口 | 无 |
| 访问层代码 | `src/store/useWardrobeStore.ts`（zustand 状态 + 存储持久化） |
| 容量限制 | 微信本地缓存：单 key ≤ 1MB，全部 key 合计 ≤ 10MB |
| 登录/网络 | MVP 阶段无登录、无同步；唯一网络请求为天气数据获取 |

> 说明：MVP 阶段按 PRD 6.3 采用「先本地后云端」策略，存储访问层与业务解耦，后续版本引入微信登录与云端存储时可整体替换实现。届时本文档需补充云端数据库的地址、端口、鉴权方式等信息。

## 2. 集合（表）清单

`ldw_data_v1` 单文档内包含以下逻辑集合：

| 集合 | 说明 |
| --- | --- |
| `wardrobes` | 衣橱（一位用户/家人的独立衣物集合） |
| `items` | 衣物条目（隶属某个衣橱） |
| `tryoutItems` | 备选条目（准备购入的试穿/展示信息，v0.5 新增） |
| `customOptions` | 用户自定义属性选项（类型/颜色/材质/尺码/场合） |
| `counters` | 衣物命名流水号计数器 |
| `bodyProfiles` | 个人身体数据（v0.6 起按衣橱归属，key = 衣橱id，切换衣橱联动；旧版全局 `bodyProfile` 已迁移） |
| `favoriteBrands` | 喜爱品牌列表（v0.5 新增） |
| `diaryEntries` | 着装日记（v0.6 新增，按日期记录当天着装照片） |
| `tomorrowOutfits` | 明日穿搭勾选（v0.6 新增，key = 衣橱id，value = 衣物id 数组） |
| `city` | 天气城市（空 = 未选择） |
| `currentWardrobeId` | 当前选中衣橱 id |

> 运行时字段 `wardrobeFilterPreset`（首页待应用筛选预设）不持久化，每次写入存储时恒为 null。
> v1.9.0 起 store 另有 `memberTier`（会员档位）/ `memberUsage`（会员权益用量）本地字段，随主文档持久化，结构见 `src/services/entitlement.ts`。

此外，v1.9.0（F-19 会员）起新增**微信云开发数据库集合**（环境 `laodengwardrobe-d7fyycr6954804b4`，访问层 `cloudfunctions/member`）：

| 集合 | 说明 |
| --- | --- |
| `members` | 云端会员档位（openid 维度；**v2.0.0 起为档位唯一权威**，微信支付回调 payCallback 写入，结构见 3.14.1） |
| `orders` | 会员开通订单流水（**v2.0.0 微信支付正式接入**，status: `created`→`paid`/`failed`，结构见 3.14.2） |
| `seasonal_images` | 当季推荐图组缓存（v1.13.0，主键 = 日期_季节_性别_年龄段_风格；v1.14.0 起风格支持自定义键 `c_<md5 前 10 位>`，记录云存储 fileID 与状态） |
| `seasonal_usage` | 当季图组月度生图用量（v1.13.0，主键 = YYYY-MM；用于预算熔断） |
| `users` | 云同步用户档案（**v1.15.0 新增**，openid 维度，服务端权威会员档位/数据版本/照片容量计量，访问层 `cloudfunctions/userSync`） |
| `wardrobe_snapshots` | 云同步全量快照（**v1.15.0 新增**，每用户 1 条，仅含同步范围数据，见 3.14） |
| `sync_conflicts` | 同步冲突副本（**v1.15.0 新增**，快照级冲突三选一数据源，统一保留 30 天） |

> 云开发集合需在开发者工具云开发控制台手动创建；`users`、`wardrobe_snapshots`、`sync_conflicts` 权限必须为「仅管理端可读写」（客户端只能经云函数访问，见设计方案 §9）。本地集合与云端集合的同步策略见《云端同步设计方案-v1.13.0》（R-5，v1.15.0 M1 已落地）。

## 3. 表结构

### 3.1 `wardrobes`（衣橱）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键，`genId()` 生成 |
| `name` | string ≤10 字 | 是 | 用户名称（衣橱标识），创建后不可修改，不可重名 |
| `color` | string | 是 | 主题色（取自所选风格主题主色，如 `#B07D50`） |
| `gender` | `'male' \| 'female'` | 是 | 衣橱主人性别（v0.5） |
| `age` | number \| null | 否 | 衣橱主人年龄，null = 未填写（v0.5） |
| `themeId` | `'warm' \| 'ocean' \| 'mint' \| 'honey' \| 'rose' \| 'ink'` | 是 | 风格主题（v0.5） |
| `createdAt` | number | 是 | 创建时间（epoch 毫秒） |

### 3.2 `items`（衣物条目）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `wardrobeId` | string | 是 | 外键 → `wardrobes.id` |
| `photos` | string[]（1–9） | 是 | 照片组（云存储 fileID 或本地路径，云同步上传后回填 fileID），第 1 张为主图 |
| `name` | string | 是 | 系统按「用户-服装类型-编号」自动命名，允许手动修改 |
| `renamed` | boolean | 是 | 用户是否手动改过名（改名后名称不再随类型联动） |
| `type` | string | 是 | 服装类型（预设或自定义） |
| `layer` | string | 是 | 内外穿：`内穿 / 外穿` |
| `color` | string | 是 | 颜色（预设或自定义） |
| `material` | string | 是 | 材质（预设或自定义） |
| `seasons` | string[]（1–4） | 是 | 穿着季节：`春 / 夏 / 秋 / 冬` |
| `size` | string | 否 | 尺码（XS–XXL 或自定义），可空字符串 |
| `brand` | string ≤20 字 | 否 | 品牌，可空字符串 |
| `occasions` | string[] | 否 | 适用场合：日常/通勤/运动/正式/居家/旅行 |
| `purchase` | object | 否 | 购入信息（v0.5），子字段：`date`（YYYY-MM-DD）、`place`、`price`（元）、`photo`（凭证照片路径） |
| `favorite` | boolean | 是 | 喜爱标记，默认 false |
| `remark` | string ≤200 字 | 否 | 备注 |
| `createdAt` | number | 是 | 录入时间（epoch 毫秒），列表按此倒序 |

### 3.3 `tryoutItems`（备选条目，v0.5）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 主键 |
| `wardrobeId` | string | 是 | 外键 → `wardrobes.id` |
| `photos` | string[] | 是 | 试穿/展示图片（云存储 fileID 或本地路径；v1.21.0 起随云同步上传并回填 fileID） |
| `name` | string | 是 | 备选名称（默认「未命名备选」） |
| `type` | string | 否 | 期望服装类型（转正式衣物时预填） |
| `color` | string | 否 | 颜色 |
| `brand` | string | 否 | 品牌 |
| `size` | string | 否 | 尺码 |
| `price` | string | 否 | 期望价格（元） |
| `note` | string | 否 | 试穿感受/备注 |
| `createdAt` | number | 是 | 创建时间（epoch 毫秒） |

### 3.4 `customOptions`（自定义属性选项）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `dimension` | `'type' \| 'color' \| 'material' \| 'size' \| 'occasion'` | 是 | 所属维度 |
| `value` | string | 是 | 选项文本（长度上限按维度：类型 10 / 颜色 6 / 材质 10 / 尺码、场合见 `CUSTOM_MAX_LEN`） |

约束：`dimension + value` 联合唯一；已被任一衣物使用的自定义选项不可删除。

### 3.5 `counters`（命名流水号计数器）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 键 | string | `${wardrobeId}__${服装类型}` |
| 值 | number | 该衣橱该类型下已分配的最大编号（001 起递增，删除不回收） |

### 3.6 `bodyProfiles`（个人身体数据，v0.6）

键值表：`Record<衣橱id, BodyProfile>`，每位衣橱主人一份，切换衣橱联动；全部字段选填（number，缺失即未填写）：

| 字段 | 单位 | 说明 |
| --- | --- | --- |
| `height` | cm | 身高 |
| `weight` | kg | 体重 |
| `bust` | cm | 胸围 |
| `waist` | cm | 腰围 |
| `hip` | cm | 臀围 |
| `shoulderWidth` | cm | 肩宽 |
| `shoulder` | cm | 肩围 |
| `armSpan` | cm | 臂展 |
| `neck` | cm | 领围 |
| `inseam` | cm | 裤长 |
| `thigh` | cm | 腿围 |
| `footLength` | mm | 脚长（鞋码参考） |

> v0.6 变更：由全局 1 份（`bodyProfile`）改为按衣橱归属（`bodyProfiles`）；读取旧数据时自动将旧全局数据迁移到当前衣橱名下。

### 3.10 其他标量

### 3.11 `seasonal_images`（云端当季图组缓存，v1.13.0，v1.14.0 起支持自定义风格键）

集合：`seasonal_images`，写入方 `cloudfunctions/seasonalImages`，主键 `_id` = `${dateKey}_${season}_${gender}_${ageGroup}_${style}`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 缓存键：日期_季节_性别_年龄段_风格 |
| `fileID` | string | 是 | 云存储 fileID（`cloud://`，图片已转存，非临时 URL） |
| `status` | `'ready' \| 'failed'` | 是 | 生成状态，ready 命中缓存 |
| `dateKey` | string | 是 | 北京时间日期 YYYY-MM-DD |
| `season` | string | 是 | `spring \| summer \| autumn \| winter` |
| `gender` | string | 是 | `male \| female \| other` |
| `ageGroup` | string | 是 | `teen \| young \| middle \| senior` |
| `style` | string | 是 | 默认风格 `daily \| commute \| street \| sport \| smart \| weekend \| couture \| detail`（v1.14.0 风格池扩充）；自定义风格为 `c_<md5(原文) 前 10 位>` |
| `label` | string | 是 | 展示标签（默认风格 label 或自定义风格原文，v1.14.0） |
| `custom` | boolean | 否 | 是否自定义风格生成（v1.14.0 新增；true 时 `style` 为 `c_*` 键、`label` 为用户原文） |
| `prompt` | string | 是 | 生图提示词快照（便于回溯与调优） |
| `updatedAt` | number | 是 | 写入时间（epoch ms） |

映射关系（v1.14.0 调整为按需生成）：档位决定**每日可生成张数**（普通 0 不生图不写入 / VIP 1 / SVIP 2，前端 `memberUsage.seasonalViewed` 计数），风格由用户点击传入（VIP 可选 6 个默认风格，SVIP 额外解锁 `couture`、`detail`；自定义风格文本 ≤12 字转 `c_*` 缓存键）。生图模型为 `hy-image-v3.5-preview`（Hy-Image-3.5-Preview）。同组合命中缓存直接返回、不重复计费。

### 3.12 `seasonal_usage`（当季图组月度用量，v1.13.0）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 月份 `YYYY-MM`（北京时间） |
| `images` | number | 是 | 本月已生成图片张数（原子自增） |
| `budget` | number | 否 | 首次创建时记录的月度预算（元） |
| `costPerImage` | number | 否 | 首次创建时记录的单张估算成本（元） |
| `updatedAt` | number | 是 | 更新时间（epoch ms） |

> 预算熔断：环境变量 `SEASONAL_BUDGET_YUAN`（默认 30 元）、`SEASONAL_COST_PER_IMAGE`（默认 0.2 元/张），超预算返回 `BUDGET_EXCEEDED`，前端使用本地图组兜底。

### 3.13 云同步集合（v1.15.0 M1 已落地，访问层 `cloudfunctions/userSync`）

云函数 action：`ping / login / setTier / pull / push / deleteCloud / photoStat`（v1.17.0 新增 `setTier` 档位上行）。同步协议、合并规则与状态机见《云端同步设计方案-v1.13.0》第 4–6 章。v1.19.0 起支持单端互踢：`login` 上报 `deviceId` 写入 `users.activeDeviceId`（新设备顶掉旧设备）；`pull / push / photoStat` 携带 `deviceId`，非活跃设备返回 `code: 'KICKED'`（未携带 `deviceId` 的旧客户端跳过校验）。

#### 3.13.1 `users`（用户档案，openid 维度，1 用户 1 条）

主键 `_id` = 微信 openid（微信静默授权登录写入，全程无弹窗）。权限：仅管理端可读写。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 微信 openid |
| `tier` | `'free' \| 'vip' \| 'svip'` | 是 | 服务端权威会员档位；v2.0.0 起档位唯一权威为 `members` 订单校验（微信支付回调 payCallback 写入）——客户端上报回落与 setTier 通道已随测试模式移除，档位不可由客户端改写；换设备登录自动恢复已购权益 |
| `dataVersion` | number | 是 | 云端当前数据版本号（单调递增，push 乐观锁基准） |
| `photoBytes` | number | 是 | 已用照片容量（字节，`photoStat` 按增量累计；VIP 500MB / SVIP 2GB 上限） |
| `createdAt` | number | 是 | 首次登录时间（epoch ms） |
| `updatedAt` | number | 是 | 最后更新时间（epoch ms） |
| `deletedAt` | number \| null | 否 | 「删除云端数据」标记（30 天宽限期内登录自动恢复；过期物理清理在 M3 定期任务落地） |
| `activeDeviceId` | string | 否 | **v1.19.0 新增**：当前活跃设备标识（客户端本地生成持久化，登录时上报写入；单端互踢判定依据，新登录覆盖） |
| `deviceLoginAt` | number | 否 | **v1.19.0 新增**：活跃设备最近登录时间（epoch ms） |

#### 3.13.2 `wardrobe_snapshots`（全量快照，每用户 1 条）

主键 `_id` = openid。权限：仅管理端可读写。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | openid |
| `dataVersion` | number | 是 | 与 `users.dataVersion` 保持一致 |
| `updatedAt` | number | 是 | 快照更新时间（epoch ms） |
| `data` | object | 是 | 同步范围数据（结构见 3.14） |

#### 3.13.3 `sync_conflicts`（冲突副本，快照级，统一保留 30 天）

主键 `_id` 自动生成。权限：仅管理端可读写。push 版本冲突时写入，不覆盖任何一方；客户端「我的 → 云同步」三选一处理后 M2 做状态流转。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `_id` | string | 是 | 自动生成 |

| `localVersion` / `remoteVersion` | number | 是 | 冲突双方版本号 |
| `localData` / `remoteData` | object | 是 | 双方快照数据 |
| `status` | `'pending' \| 'resolved'` | 是 | 处理状态 |
| `createdAt` | number | 是 | 产生时间（epoch ms） |

### 3.14 云端快照数据结构（`wardrobe_snapshots.data`，同步范围见设计方案 4.4）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `wardrobeIds` | string[] | 本快照同步的衣橱 id 集合（VIP ≤2 / SVIP 全部），两端一致口径 |
| `wardrobes` | object[] | 所选衣橱实体（含 `updatedAt`，合并新者胜依据） |
| `items` | object[] | 所选衣橱内衣物（照片为云存储 fileID 或本地路径，`updatedAt` 同上） |
| `diaryEntries` | object[] | 所选衣橱着装日记 |
| `tryoutItems` | object[] | 所选衣橱备选条目（照片为云存储 fileID 或本地路径，v1.21.0 起随同步上传） |
| `customOptions` | object[] | 全局自定义选项（dimension + value 并集合并） |
| `customScenes` | string[] | 自定义搭配场景（并集合并） |
| `favoriteBrands` | string[] | 喜爱品牌（并集合并） |
| `bodyProfiles` | object | `Record<衣橱id, BodyProfile>`，仅所选衣橱（本地优先合并） |
| `counters` | object | `${衣橱id}__${服装类型}` 编号计数器（按 key 取 max 合并） |
| `memberUsage` | object | **v1.19.0 新增**：会员用量计数（全局，不按衣橱裁剪）——`day/month` 窗口标识、`seasonalViewed`、`tripUsed`、`batchImportUsed`、`fashionUsed`、`dailyOutfitUsed`（`Record<衣橱id, 当日已生成套数>`）；窗口一致时各计数取 max 合并，窗口不一致以本地为准 |
| `currentWardrobeId` | string | 当前衣橱（不在所选集合时回落到所选集合第一个） |

> **不上云**：明日穿搭勾选 `tomorrowOutfits`、推荐缓存 `dailyOutfits`（仅其当日生成套数经 `memberUsage.dailyOutfitUsed` 上云，v1.19.0）、推荐方案与 AI 推荐图、天气城市 `city/citySource`、临时标记 `wardrobeFilterPreset`、本地会员档位 `memberTier`（以 `members` 为准）。云存储照片目录：`user/{openid}/items/{itemId}/{n}.jpg`、`user/{openid}/diary/{entryId}/{n}.jpg`、`user/{openid}/tryout/{tryoutId}/{n}.jpg`（试穿照片目录 v1.21.0 新增）。

### 3.14.1 `members`（云端会员档位，v2.0.0 起为档位唯一权威）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `openid` | string | 是 | 用户微信 openid（openid 维度一单一档，查询键） |
| `tier` | `'vip' \| 'svip'` | 是 | 已购档位（payCallback 写入，仅升不降：vip→svip 升档允许，反向忽略） |
| `orderId` | string | 是 | 最近一次支付订单 `orders._id` |
| `paidAt` | number | 是 | 最近支付完成时间戳（ms） |
| `createdAt` / `updatedAt` | number | 是 | 创建/更新时间戳 |

> 写入方：仅 `payCallback`（云开发微信支付回调，管理端权限）；读取方：`member` 云函数 `getMember`（登录态校验档位）、`userSync` `tierFromOrders`（login 返回档位的唯一权威来源，v2.0.0 起 `users.tier` 仅作展示缓存回写）。

### 3.14.2 `orders`（会员开通订单流水）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `openid` | string | 是 | 下单用户 openid |
| `tier` | `'vip' \| 'svip'` | 是 | 购买档位 |
| `totalFee` | number | 是 | 支付金额（分）：VIP 1990 / SVIP 2990（回调按此验额，防篡改） |
| `payMode` | `'once'` | 是 | 付费模式：一次买断永久有效 |
| `outTradeNo` | string | 是 | 商户订单号（`LDW` + 时间戳 + 3 位随机，≤32 字符，微信支付侧唯一键） |
| `status` | `'created' \| 'paid' \| 'failed'` | 是 | 订单状态：下单 → 支付成功/未完成 |
| `transactionId` | string | 否 | 微信支付交易单号（payCallback 回填） |
| `paidAt` | number | 否 | 支付完成时间戳（payCallback 回填） |
| `createdAt` / `updatedAt` | number | 是 | 创建/更新时间戳 |

> 写入方：`member.createOrder` 登记 `created`；`payCallback` 置 `paid`/`failed` 并回填交易信息。权限建议「仅管理端可读写」（客户端只经云函数访问）。

## 4. 表关系

```text
wardrobes (1) ──< (N) items          items.wardrobeId → wardrobes.id（删除衣橱时级联删除）
wardrobes (1) ──< (N) tryoutItems    tryoutItems.wardrobeId → wardrobes.id（删除衣橱时级联删除）
wardrobes (1) ──< (N) diaryEntries   diaryEntries.wardrobeId → wardrobes.id（删除衣橱时级联删除，v0.6）
wardrobes (1) ──< (N) counters       counters 键内嵌 wardrobeId（删除衣橱时清理对应键）
wardrobes (1) ── (1) bodyProfiles    bodyProfiles[wardrobeId]（v0.6，删除衣橱时清理对应键）
wardrobes (1) ── (1) tomorrowOutfits tomorrowOutfits[wardrobeId]（v0.6，删除衣橱时清理对应键）
favoriteBrands / city / currentWardrobeId   全局标量，无外键
```

- 删除衣橱级联：删除 `wardrobes` 记录时，同步删除其下全部 `items`、`tryoutItems`、`diaryEntries`，清理 `counters`、`bodyProfiles`、`tomorrowOutfits` 中的对应键；最后一个衣橱不可删除。
- 命名联动：`items.name` 由 `wardrobes.name` + `type` + `counters` 流水号生成；`wardrobes.name` 创建后不可修改，保证已生成名称不失来源。

## 5. 版本与迁移

1. 存储键 `ldw_data_v1` 后缀 `v1` 为数据结构版本号；发生不兼容结构变更时递增键版本或编写迁移逻辑。
2. 现有迁移逻辑位于 `loadData()` / `migrateWardrobe()`：读取旧数据时补齐 v0.3 主题色字段与 v0.5 新字段（`gender` / `age` / `favoriteBrands` / `tryoutItems`）；v0.6 新增迁移：旧全局 `bodyProfile` 归属到当前衣橱（`bodyProfiles[currentWardrobeId]`），并补齐 `diaryEntries` / `tomorrowOutfits` 默认值；v1.9.0 新增迁移：旧数据补 `memberTier='free'` 与 `memberUsage` 初始值（天/月窗口滚动重置）；v1.15.0 新增迁移：旧数据补 `syncMeta`（未登录/无脏标记）、`syncWardrobeIds=null`（登录后按档位初始化）、`cloudSyncEnabled=false`（云同步开关默认关闭），性别默认值由女改为男（缺 `gender` 的旧数据同样兜底为男）。
3. 每次结构变更必须：更新本文件并递增文档版本号 → 提交推送 GitHub（见文首维护规则）。
