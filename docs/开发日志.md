### 5. v0.5.0 修复：衣物属性「其他」「材质」无法自定义的问题

**版本**：v0.5.0（公网测试版修复补丁）
**修改时间**：2026-11-08 +08:00

**问题定位**：v0.5 初版虽提供「✎ 将「其他」改为自定义内容」入口，但该按钮位于选中值下方、样式弱且需二次点击，用户实测反馈仍"无法自定义"。

**修复方案**（OptionSelector 组件重构交互）：

1. 选中「其他」（服装类型/材质等含兜底项的单选维度）后，**立即自动展开内联输入框**（主色描边，带提示文案），输入内容**实时替代「其他」**，无需点击任何按钮；
2. 清空输入框时恢复为「其他」，语义闭环；
3. 重选其他选项或经「+ 新增选项」入库自定义值时，内联输入框自动收起；
4. 非兜底选项仍保留「✎ 改为自定义内容」入口与「+ 新增选项」入库路径。

**验证**：`npm run build:weapp` 通过（11.7s）；浏览器实测材质维度全链路 PASS（选「其他」→ 出现输入框 → 输入「雪纺」→ 值实时替换）；服装类型走同一组件同一代码路径（H5 WeUI 转盘弹层滚动无法自动化操作，人工测试以滑动选中为准）。公网地址不变（HMR 自动生效）：https://wise-papayas-cross.loca.lt

**修改时间**：2026-11-08 +08:00

### 7. 环境修复：将 `.git` 排除出 SynologyDrive 同步范围

**背景**：git 操作过程中多次出现 `.git` 内部文件（index、HEAD、config、index.lock 等）被移入回收站的事件，经排查疑似为 SynologyDrive 同步客户端与 git 写锁相互干扰所致。

**处理**：

| 步骤 | 内容 |
| --- | --- |
| 定位 | Synology Drive 客户端用户级排除规则位于 `%LOCALAPPDATA%\SynologyDrive\data\blacklist.filter`（INI 格式） |
| 停止进程 | 停止 cloud-drive-ui / cloud-drive-connect / cloud-drive-daemon |
| 修改配置 | `[Directory]` 区块新增 `black_name = ".git", "node_modules", ".pai", ".auth"` |
| 重启客户端 | 通过 `SynologyDrive.app\bin\cloud-drive-ui.exe` 重启，配置未被覆盖、进程恢复正常 |

**说明**：同步排除为双向生效（本地与 NAS 均不再同步这些目录）；此前已同步到 NAS 的 `.git` 副本为历史残留，不影响本地仓库使用。
